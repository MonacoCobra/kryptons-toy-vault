# Catalog sharding

GitHub rejects files over 100 MB. These three datasets are stored as 64 shards
so the app and the ingest bot can keep growing them without another monolith.

Callers still pass the old paths. `scripts/data_shards.py` maps each path to
its directory:

| Legacy path (what callers pass) | Directory |
| --- | --- |
| `src/data/comics.ts` | `src/data/comics/` |
| `src/data/comic-upc-map.json` | `src/data/comic-upc-map/` |
| `src/data/figure-archive/product-sku-index.json` | `src/data/figure-archive/product-sku-index/` |

`src/data/comics.ts` is only the app loader. Row data lives in the shards.

## Layout

```
<dataset>/manifest.json
<dataset>/shards/<id>.json
<dataset>/.lock          # runtime only, not committed
```

`manifest.json` lists shard ids and counts and sets `shardCount` to **64**.
Do not change `shardCount` without rewriting every row into new buckets.

Shard ids are lowercase hex `00`–`3f`. A shard file is omitted when it would
be empty, and it is not listed in the manifest.

Comics shard:

```json
{ "entries": [ { "seq": 0, "row": ["catalog-id", "..."] } ] }
```

`seq` is the catalog order (the old `comics.ts` array order). New rows append
after the current max.

UPC-map shard (`entries` is catalog id → entry):

```json
{ "entries": { "catalog-id": { "upc": "...", "source": "locg" } } }
```

SKU-index shard (`record.id` is the key):

```json
{ "entries": [ { "seq": 0, "record": { "id": "shop:handle", "...": "..." } } ] }
```

The app merges comics in `src/data/comics/load.ts` and the UPC map in
`src/data/comic-upc-map/load.ts`. `shard-list.ts` in those two directories is
generated by the writer when the set of shard files changes. Each shard is
imported as `?raw` and `JSON.parse`d so the typechecker does not build a union
of every catalog literal.

## Assignment

```
sha256(utf-8 key) → first 4 bytes as a big-endian integer → mod 64
```

| Dataset | Key |
| --- | --- |
| Comics | catalog id, `row[0]` |
| UPC map | object key |
| SKU index | `record.id` |

Do not assign by publisher, year, or id prefix. Ids such as `dc-det-n52-488`
reuse a modern prefix for a 1980s issue, so a prefix bucket overflows.

## Writer API

`scripts/data_shards.py`. Import it from other scripts. Pass the legacy path.

- `append_comic_rows(path, rows, note=...)` — appends rows, skips ids already
  present, returns the number appended. A no-op does not rewrite shard bytes.
- `save_map_atomic(path, local, merge_fn)` — exclusive lock on
  `src/data/comic-upc-map/.lock` (the dataset `.lock`). Reads the disk map,
  calls `merge_fn(disk, local)`, writes only shards whose bytes changed.
  A no-op merge does not rewrite shard bytes.
- `save_upc_map_atomic` in `scripts/backfill-comic-upcs.py` calls
  `save_map_atomic` with `merge_upc_maps`. When both sides have a UPC and they
  differ, an existing `locg` or `metron` source wins over gcd, shop, and
  anything else.
- `load_array(path)` / `save_array(path, rows)` — product SKU index. An
  identical list does not rewrite shard bytes.
- `comics_meta(path)` — id → series, issue, publisher, variant, upc, cover,
  coverDate, format, demand, key, plus `gcdIssueId` / `locgId` when the row
  extra has them.
- `comic_id_sets(path)` — `(ids, series|issue|publisher keys lowercased)`.
- `ids_from_comic_rows(rows)` — set of `row[0]`.
- `dataset_exists(path)` — true when a manifest or a legacy monolith is present.
- `load_document` / `save_document` — used by `load_json` / `save_json` in the
  backfill scripts when the path is one of the three datasets. Other JSON
  files stay single files.

```bash
python3 scripts/data_shards.py verify
python3 scripts/data_shards.py shard-id dc-det-n52-488
```

`verify` reloads every shard, checks bucket assignment, `shardCount == 64`,
and that the merged content hash equals `manifest.contentHash`. The hash is
sha256 of canonical JSON (`sort_keys`, compact separators, UTF-8).

These stay single files (each is well under 40 MB): `oneshot.json`,
`product-image-index.json`, `figure-sku-aliases.json`, `figure-image-urls.json`,
`comic-cover-urls.json`.
